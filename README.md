# AI 协同办公 · 智能格式审查助手

这是一个面向 Word 文档格式审查与 Word/PDF 内容审查的 Web 应用：上传 `.docx` 文件并描述格式要求后，DeepSeek 会提取结构化规则，后端确定性规则引擎再逐项检查并给出可定位的违规报告。

> 格式是否合规始终由确定性后端代码判断。独立的 AI 内容审查由 DeepSeek 提供措辞、语法、逻辑和一致性修改建议。

## 功能

- JWT 登录、注册与工作区隔离。
- `.docx`、`.pdf` 上传与浏览器预览；PDF 按页提取文字，扫描页使用本地离线 OCR。
- 自然语言生成格式规则，并提供毕业论文、商务报告快捷示例。
- 文本模板规则提取：上传带语义标题的标准 `.docx` 后，系统识别章节锚点和各章节正文主样式，用户可将区域设为固定章节、可变章节或忽略，并分别控制必填与格式检查；审查时按章节映射，不要求模板与报告逐段对应。第二期同时识别目录、图题注、表题注和代码块，可检查目录与正文一致性、题注编号连续性及专用样式；规则历史会展示相邻版本的结构与文档级检查差异。没有语义标题的旧模板仍使用完整样式候选方式。确认结果只载入草稿，点击“创建规则”才保存；临时副本会被清理，整个过程不调用 DeepSeek。
- 可视化编辑正文、标题、页面等常用规则，无需重新调用 AI。
- “文本模板审查 → 模板规则”支持从空白表单直接创建规则，不需要先在左侧选择内置模板或已有规则；手动创建不会调用 DeepSeek，并从创建时开始保留版本历史。
- 格式审查按类别汇总和筛选；点击违规行可定位并高亮对应段落。
- 格式审查检查各个文字片段和所有页面节，识别继承标题及自动编号，区分倍数、固定值和最小值行距；属性无法解析时列为“无法判断”，不报告合规，也不自动修订。空规则或没有匹配检查区域时不能显示通过。旧解析缓存会在重新审查时按解析器版本更新。
- 单条或批量审查；工作区概览按每份文档的最新结果汇总通过状态与问题分布。
- 内置毕业论文、商务报告、会议纪要规则模板；可将当前规则另存为仅当前工作区可见的自定义模板，并支持套用、删除；每次保存都保留可恢复的规则版本。
- 切换文档会自动展示该文档最新的格式审查结果，右侧格式历史也按文档隔离；格式审查记录可单独删除。
- 内容审查：选择文档 → “文本模板审查” → “内容审查” → “用 DeepSeek 审查内容”，无需格式规则。
  展示原文引用、问题原因、修改建议，点击引用或“定位原文”跳转高亮；历史按文档隔离，每页加载 50 条，可继续加载更早记录，并可删除单条记录。
  文字发送至后端配置的 DeepSeek 服务，建议需人工确认，不自动修改原件。
  当前范围为正文和表格，不含页眉页脚、图片、文本框及已删除修订；
  每次最多 30000 字符、1500 个非空段落，最多输出 50 条建议，超限明确提示拆分。
  无联网事实核查，存疑的外部事实仅标记“事实待核实”。
- 可选长文分段模式：最多 60000 字符、3000 个非空段落，单段不超过 30000 字符；需要用户勾选，会产生多次模型请求，最多两路并发。全部分段完成后基于连续原文节选复核跨段一致性；复杂关联仍需人工核实。主引用及关联依据都须匹配原文，任一模型调用或引用校验失败时不保存成功记录。
- “文本模板审查”与“表单模板审查”为同级页签。文本模板的上传、候选样式确认、规则编辑，以及格式／内容审查的选择与执行均在“文本模板审查”内部；可单选或同时勾选后点击“开始文本审查”。格式结果与内容建议使用各自独立的子页签和统计，格式历史与规则 JSON 也收纳在内部。未保存的规则须先保存，避免按旧规则审查。文档预览与修订副本为两类模板审查共用功能。
- 修订后副本：可在“格式审查”勾选支持自动修订的格式项（包括模板固定章节标题文字），或在“内容审查”中确认每条建议的替换文本，再一键下载新的 `.docx`。缺失章节、目录项和编号断档只提示人工处理，不自动编造结构。
  后端只按已存储的规则期望值和用户确认文本做确定性修订，不调用 AI 改文档；原始文件始终不变，副本末尾附“修订清单”。
  新内容审查会显示“推荐修订文本”，接纳时自动带入编辑框，用户可保留、修改或改填自己的文字。
- 表单模板审查：每个工作区保存一个“当前表单模板”。用户上传填写好的 `.docx` 标准样例后，系统提取正文、标题、简单表格和页面格式，并进入待确认状态。
  在“表单模板审查”页可把每个区域标记为固定内容、可变字段或忽略，设置必填、数字、日期、身份证号、电话号码、电子邮箱等字段约束，以及是否继承模板格式；保存并发布后才可用于审查。
  表格字段按已知标签、相邻填写值和表头关系识别；不能可靠命名时标为低置信度、等待人工核对，不把样例值猜作字段名；低置信度字段须修改或勾选“已核对”才能发布。已有模板可点击“重新识别字段”应用最新逻辑，再由用户确认发布。
  可变字段可以提出具体填写要求，并将支持的文字要求转换为可编辑规则草案：邮箱格式、字符／汉字长度、数值范围、限定选项、包含文字、与另一字段一致。无法解析的要求会明确提示，不会静默执行；规则随模板版本发布并保存在报告快照中，违规内容定位到待审区域，不自动编造修订值。
  固定文字及已有文字的字段规范问题可以接纳推荐值或自行填写替换值；支持的正文与页面格式可确定性修复。缺失结构、空白必填项和未知事实只提示人工处理，不自动编造或插入内容。
  上传新模板会生成新版本并成为当前版本，旧版本保留在配置页的版本下拉框中，可随时重新启用，无需独立模板中心。
- 已发布表单模板的修改和重新识别均产生新版本，保留旧配置；草稿未发布时审查沿用原先选定的已发布版本。新报告保存不可变模板快照，历史预览使用报告对应的模板；旧记录没有快照时明确标注。结构数量、表格形状或固定标签位置发生变化时，暂停自动修订，要求人工核对区域映射。
- 删除文档会同时删除其格式、内容和表单审查历史；删除确认后不可恢复。数据库提交失败时恢复原文件；启动时清理早期遗留的孤立审查记录。SQLite 每个连接均开启外键约束。
- 文档、规则和格式历史接口支持 `limit`、`before_id` 游标分页；工作区初始仅加载各文档最新报告，选中文档后加载其历史。修订仅影响选中的文字片段和页面节，冲突或重叠建议不能同时应用。
- “文档深度审查 → 版本对比与复审”：选择同一工作区的原稿、修改稿及格式规则，查看文字变化、样式变化和格式问题的已解决／仍存在／新增／待确认状态。段落无法可靠对应时标为待确认，不把删除误报为修复。
- “文档深度审查 → 章节与图表完整性”：输入必需章节文字及顺序，按文档文字是否出现检查缺章（不要求标题格式），按首次出现位置检查顺序，并检查图表题注重复或缺号、正文引用没有对应题注。每条发现提供源文档段落入口。
- “文档深度审查 → 跨文档数据核对”：选 2–10 份 Word/PDF 材料，明确指定基准文档，并逐项配置字段名、别名和文字／数值／日期类型。系统只匹配“字段名：值”文本；多处候选、缺失或无法规范化时列为待确认，展示来源，不由 AI 猜测基准。
- PDF 可在“文本模板审查 → 内容审查”中调用 DeepSeek，并按 PDF 页码定位原文。扫描页识别仅在本机运行；只有点击内容审查时，提取出的文字才会发送给 DeepSeek。PDF 不参与 Word 格式审查、表单模板审查或自动修订。PDF 审查建议需对照原页人工核实。
- 当前结果可单独导出 `.docx` 审查报告：格式审查导出当前选中的完整记录（即使页面按类别筛选），内容及表单审查导出当前选中的历史记录，深度审查导出当前页面的版本、结构或跨文档结果。每项列出文件名、可核对的原文位置与引用、问题说明和修改建议；Word 定位到正文段落或表格行列／页面节，PDF 定位到页码，不推断 Word 的排版页码。无法精确定位时明确提示人工确认。报告按需在内存中生成，不调用 DeepSeek、不写入服务端报告历史；删除文档后无法再次导出相关结果。

创建自定义模板：先生成或选择一条格式规则，进入“文本模板审查 → 模板规则”，调整所需格式后点击“存为模板”；模板会保存到当前工作区，可在左侧“添加规则”直接套用或删除。

### 表单模板审查使用流程

1. 进入“表单模板审查”，上传一份填写好的 `.docx` 标准样例。
2. 检查自动提取的区域，重点核对低置信度字段的名称、用途、必填和字段类型；可为可变字段设置具体填写要求并核对生成的规则草案。
3. 点击“保存并发布配置”。未发布的模板不会参与审查。
4. 选择待审文档并执行表单模板审查，在左右预览中对比定位问题。
5. 对支持修订的问题选择“接纳并修订”，必要时填写准确的替换文字。
6. 使用页面顶部“生成修订后副本”下载新文件；上传原件不发生变化，副本末尾附修订清单。

当前表单模板审查支持 `.docx` 的顶层正文、标题、常规页面设置和简单表格。复杂合并/嵌套表格、文本框、图片、页眉页脚、签章和像素级版式不自动判定；系统会保留需要人工核实的问题，不执行不确定修改。

### 新增审查能力使用与边界

进入“文档深度审查”后选择上述三个子功能。版本复审和章节检查仅支持 `.docx`；跨文档字段核对可混用 `.docx` 与 `.pdf`。三个分析结果按需生成，目前不保存独立历史；删除文档时也不会保留这些结果。章节识别依赖 Word 标题层级，图表检查基于“图 1／表 1”等显式编号；复杂交叉引用、隐藏域及目录域不作确定性判断。跨文档字段需要显式标签和冒号；非结构化散文中的隐含数据不自动推断。

PDF 上传上限为 60 页、5000 行可提取文字、10 万字符，仍受通用文件大小及工作区配额限制。PDF 文字提取由 `pdfplumber` 完成；没有文字的页面用本地 Poppler `pdftoppm` 渲染，再用 Tesseract 的 `chi_sim+eng` 识别。需要在运行后端的机器上安装 Poppler、Tesseract 及简体中文语言包，并确保 `pdftoppm`、`tesseract` 可执行，或在 `.env` 中设置 `PDFTOPPM_COMMAND`、`TESSERACT_COMMAND` 为对应可执行文件路径。语言模型可以放在 Tesseract 的 `tessdata` 目录，也可以在 `.env` 设置 `TESSDATA_DIR`。Windows 还会自动查找当前用户的 `%LOCALAPPDATA%/SmartFormatOCR/tessdata`（该目录需同时有 `chi_sim.traineddata` 和 `eng.traineddata`）。可用 `pdftoppm -h`、`tesseract --list-langs` 检查安装，后者应列出 `chi_sim`。扫描页如果识别失败，上传会明确报错，不会把未读到的页面当作已审查。OCR 结果可能有错字，必须核对 PDF 原页。

## 技术栈

- 前端：Vue 3、Vite、TypeScript、Pinia、Element Plus、docx-preview
- 后端：FastAPI、SQLAlchemy、Pydantic v2、python-docx、pdfplumber；扫描页另需本地 Poppler 和 Tesseract
- AI：DeepSeek `deepseek-chat`（规则提取及独立内容审查）
- 存储：SQLite（演示环境），可替换为 PostgreSQL + Redis

## 系统架构

浏览器端使用 Vue 3 完成登录、工作区管理、文档预览、规则编辑和审查结果定位；FastAPI 提供鉴权、文档解析、审查、修订与报告导出接口；SQLite 保存演示环境中的用户、工作区、规则、文档元数据与历史结果，上传原件存于本地存储目录。

AI 和确定性逻辑严格分工：DeepSeek 只负责将自然语言要求转成规则 JSON，以及输出独立的内容审查建议；`checker.py` 根据结构化规则完成格式合规判定，修订副本只执行已确认的规则值或用户确认文字。这样即使 AI 输出异常，也不会直接把它当作格式结论或写回用户原件。

```text
Vue 3 浏览器端
  ├─ 文档预览与段落定位
  ├─ 规则编辑与审查操作
  └─ 历史记录和报告下载
           │ HTTPS API
FastAPI 服务
  ├─ JWT 与工作区成员校验
  ├─ DOCX PDF 解析和离线 OCR
  ├─ DeepSeek 规则提取和内容建议
  ├─ 确定性格式检查和深度核对
  └─ 修订副本和 DOCX 报告导出
           │
SQLite 元数据和审查历史 + 本地上传文件
```

## 环境配置

运行后端前，将 [`backend/.env.example`](backend/.env.example) 复制为 `backend/.env`，再按部署环境填写。真实 `DEEPSEEK_API_KEY`、生产环境 `SECRET_KEY` 和生产域名不得提交到仓库。

| 项目 | 建议版本或要求 | 用途 |
| --- | --- | --- |
| Python | 3.10+ | FastAPI 后端与 DOCX/PDF 处理 |
| Node.js | 18+ | Vue 3 前端构建与测试 |
| DeepSeek API Key | 内容审查或自然语言规则提取时必需 | 仅后端环境变量读取 |
| Poppler 和 Tesseract | 仅扫描型 PDF OCR 需要 | 安装简体中文 `chi_sim` 与英文 `eng` 语言包 |

生产部署应设置 `ENVIRONMENT=production`、独立且不少于 32 字符的 `SECRET_KEY`，并将 `CORS_ORIGINS` 收紧为实际前端地址。SQLite 适用于演示；多用户生产部署可替换为 PostgreSQL，并把限流计数迁移到共享存储。

## 启动

### 后端

```bash
cd backend
python -m pip install -r requirements.txt
```

将 `.env.example` 复制为 `.env`，设置 `DEEPSEEK_API_KEY` 后启动：

```bash
uvicorn app.main:app --reload
```

健康检查：<http://127.0.0.1:8000/api/health>

### 前端

```bash
cd frontend
npm install
npm run dev
```

## 安全约定

- `.env` 中的 DeepSeek Key 不会提交到仓库，也不会暴露给前端。
- 所有工作区数据均经过成员关系校验。
- 规则字段以 `RuleSet` 为唯一契约；新增检查维度时须同步更新解析器、规则引擎与前端类型。

## 内容审查升级与验证

重启后端会自动创建 `content_reviews`、`rule_templates`、`document_templates` 和 `template_reviews` 表，并为早期创建的模板表补齐兼容字段，保留原有数据。已有文档可直接审查，无需重新上传或删除数据库。
后端需配置 DEEPSEEK_API_KEY；单次模型请求最长等待 120 秒，失败不写入成功记录。内容审查在单次请求超过 8000 字符或 200 段时自动按较小批次审查，可能产生多次 DeepSeek 请求；勾选“长文分段审查”时额外复核跨段节选。连接、限流、超时和无效原文引用分别给出可辨认提示，引用校验仍要求 AI 给出逐字连续原文，不能定位的建议不会作为有效结果保存。
