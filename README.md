# AI 协同办公 · 智能格式审查助手

这是一个面向 Word 文档的格式审查 Web 应用：上传 `.docx` 文件并描述格式要求后，DeepSeek 会提取结构化规则，后端确定性规则引擎再逐项检查并给出可定位的违规报告。

> 格式是否合规始终由确定性后端代码判断。独立的 AI 内容审查由 DeepSeek 提供措辞、语法、逻辑和一致性修改建议。

## 功能

- JWT 登录、注册与工作区隔离。
- `.docx` 上传、解析与浏览器预览。
- 自然语言生成格式规则，并提供毕业论文、商务报告快捷示例。
- 可视化编辑正文、标题、页面等常用规则，无需重新调用 AI。
- “编辑规则”支持从空白表单直接创建规则，不需要先在左侧选择内置模板或已有规则；手动创建不会调用 DeepSeek，并从创建时开始保留版本历史。
- 格式审查按类别汇总和筛选；点击违规行可定位并高亮对应段落。
- 单条或批量审查；工作区概览按每份文档的最新结果汇总通过状态与问题分布。
- 内置毕业论文、商务报告、会议纪要规则模板；可将当前规则另存为仅当前工作区可见的自定义模板，并支持套用、删除；每次保存都保留可恢复的规则版本。
- 切换文档会自动展示该文档最新的格式审查结果，右侧格式历史也按文档隔离；格式审查记录可单独删除。
- 内容审查：选择文档 → “内容审查” → “用 DeepSeek 审查内容”，无需格式规则。
  展示原文引用、问题原因、修改建议，点击引用或“定位原文”跳转高亮；按文档保留最近 50 次历史供查看，并可删除单条记录。
  文字发送至后端配置的 DeepSeek 服务，建议需人工确认，不自动修改原件。
  当前范围为正文和表格，不含页眉页脚、图片、文本框及已删除修订；
  每次最多 30000 字符、1500 个非空段落，最多输出 50 条建议，超限明确提示拆分。
  无联网事实核查，存疑的外部事实仅标记“事实待核实”。
- 修订后副本：可在“格式审查”勾选支持自动修订的格式项，或在“内容审查”中确认每条建议的替换文本，再一键下载新的 `.docx`。
  后端只按已存储的规则期望值和用户确认文本做确定性修订，不调用 AI 改文档；原始文件始终不变，副本末尾附“修订清单”。
  新内容审查会显示“推荐修订文本”，接纳时自动带入编辑框，用户可保留、修改或改填自己的文字。
- 模板审查：每个工作区保存一个“当前文档模板”。用户上传填写好的 `.docx` 标准样例后，系统提取正文、标题、简单表格和页面格式，并进入待确认状态。
  在“模板审查”页可把每个区域标记为固定内容、可变字段或忽略，设置必填、数字、日期、身份证号、电话号码等字段约束，以及是否继承模板格式；保存并发布后才可用于审查。
  模板中的姓名、年龄、地址等样例值不会自动视为正确答案，只有用户确认的固定内容才进行文字一致性比较。模板与待审文档可双栏预览，点击问题同时定位两侧区域。
  固定文字及已有文字的字段规范问题可以接纳推荐值或自行填写替换值；支持的正文与页面格式可确定性修复。缺失结构、空白必填项和未知事实只提示人工处理，不自动编造或插入内容。
  上传新模板会生成新版本并成为当前版本，旧版本保留在配置页的版本下拉框中，可随时重新启用，无需独立模板中心。

创建自定义模板：先生成或选择一条格式规则，进入“编辑规则”，调整所需格式后点击“存为模板”；模板会保存到当前工作区，可在左侧“规范模板”直接套用或删除。

### 模板审查使用流程

1. 进入“模板审查”，上传一份填写好的 `.docx` 标准样例。
2. 检查自动提取的区域，确认固定内容、可变字段、忽略区域、必填和字段类型。
3. 点击“保存并发布配置”。未发布的模板不会参与审查。
4. 选择待审文档并执行模板审查，在左右预览中对比定位问题。
5. 对支持修订的问题选择“接纳并修订”，必要时填写准确的替换文字。
6. 使用页面顶部“生成修订后副本”下载新文件；上传原件不发生变化，副本末尾附修订清单。

当前模板审查支持 `.docx` 的顶层正文、标题、常规页面设置和简单表格。复杂合并/嵌套表格、文本框、图片、页眉页脚、签章和像素级版式不自动判定；系统会保留需要人工核实的问题，不执行不确定修改。

## 技术栈

- 前端：Vue 3、Vite、TypeScript、Pinia、Element Plus、docx-preview
- 后端：FastAPI、SQLAlchemy、Pydantic v2、python-docx
- AI：DeepSeek `deepseek-chat`（规则提取及独立内容审查）
- 存储：SQLite（演示环境），可替换为 PostgreSQL + Redis

## 启动

### 后端

```bash
cd backend
python -m pip install -r requirements.txt
```

将 `.env.example` 复制为 `.env`，设置 `DEEPSEEK_API_KEY` 后启动：

```bash
uvicorn app.main:app --reload
```

健康检查：<http://127.0.0.1:8000/api/health>

### 前端

```bash
cd frontend
npm install
npm run dev
```

访问：<http://127.0.0.1:5173>

## 验证

```bash
# 后端测试
cd backend
python -m pytest

# 前端构建
cd frontend
npm run build
```

## 结构

```text
backend/                         FastAPI 服务
  app/services/docx_parser.py    Word 格式确定性解析
  app/services/deepseek_spec.py  格式规则提取
  app/services/deepseek_content.py 内容审查及原文引用校验
  app/services/document_content.py 内容提取及预览书签
  app/services/template_audit.py 填写样例模板提取与确定性对比
  app/services/checker.py        确定性规则引擎
frontend/                        Vue 3 客户端
  src/components/RuleEditor.vue  可视化规则编辑
  src/components/CheckHistory.vue 审查历史
  src/components/TemplateAuditPanel.vue 模板配置、双栏对比与审查报告
```

## 安全约定

- `.env` 中的 DeepSeek Key 不会提交到仓库，也不会暴露给前端。
- 所有工作区数据均经过成员关系校验。
- 规则字段以 `RuleSet` 为唯一契约；新增检查维度时须同步更新解析器、规则引擎与前端类型。

## 内容审查升级与验证

重启后端会自动创建 `content_reviews`、`rule_templates`、`document_templates` 和 `template_reviews` 表，并为早期创建的模板表补齐兼容字段，保留原有数据。已有文档可直接审查，无需重新上传或删除数据库。
后端需配置 DEEPSEEK_API_KEY；单次模型请求最长等待 120 秒，失败不写入成功记录。
前端预览改用 /api/documents/{id}/preview，需同时更新并重启后端。

离线回归：后端运行 python -m pytest；前端运行 npm run build。
启动 Vite 后可访问 /tests/content-review.browser.html，使用合成文档与模拟 AI 响应验证点击定位。
